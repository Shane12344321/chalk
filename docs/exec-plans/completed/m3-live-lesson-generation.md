## Objective

Let a student enter or speak a math/physics topic and receive a board-model-generated lesson through a validated NDJSON stream. Raw model output must never reach the renderer, stale work must be cancelled, and the accepted cached lesson must remain available when live generation fails.

## Assumptions

- `gpt-5.6-luna` is the selected qualification model and account access passed on the first bounded call. `reasoning.effort: none` is the next latency baseline; the observed low-effort call missed the target.
- The Responses API emits text through typed SSE events including `response.output_text.delta` and a terminal `response.completed` or failure event.
- Prompted JSONL can be incrementally useful, but it is not trusted. Every completed line is independently parsed and validated before projection.
- A topic request may contain student-provided text. Logs retain only request IDs, counts, timings, bounded error codes, and model configuration—not topics, student context, raw model lines, or repair payloads.

## Decisions

- Keep OpenAI SSE termination inside the backend. The browser receives CHALK-owned `application/x-ndjson` envelopes, not upstream SSE or model text.
- Use the checked-in lesson JSON Schema for step validation and a separate checked-in stream-envelope schema for browser protocol validation.
- Use a strict Python AST allowlist only as a server safety boundary. Browser mathjs sampling remains the final rendering check.
- Stream a model-authored title as metadata, then validated steps. If no step survives, terminate with a non-sensitive error and let the browser load the cached projectile lesson through the existing decoder.
- If generation fails after at least one valid step, keep and finish the accepted prefix; use the cached lesson only when zero steps survive.
- Use plain-text Responses for scoped repair and revalidate every repaired step against the shared schema and semantic state. The repair-only JSON formatting request was rejected in the second live batch, so local parsing and validation remain authoritative.
- Retain the explicit manual topic form even after `teach` is wired. It is a controllable M3 debugging and demo path, not a second lesson implementation.
- Run the live rubric through the owner-gated sequential harness with no retries. Review its captured raw NDJSON locally in diagnostics mode rather than paying to regenerate the same ten lessons for screenshots.
- Do not spend the ten-topic live-evaluation budget without the separate approval required by `AGENTS.md`.
- Keep the acceptance criteria unchanged on Luna. If Luna misses them, compare only its failed topics on Terra; do not silently combine models into a passing evidence package or rerun all ten without a new approved plan.
- Keep the one-topic access smoke and ten-topic acceptance batch as distinct CLI modes and approvals. A topic may include bounded repair calls, so operator approval must state both topic count and the underlying call ceiling. Smoke evidence is diagnostic and cannot satisfy or be silently merged into the batch exit gate.
- Keep upstream terminal semantics closed and distinct. HTTP rejection, `response.incomplete`, `response.failed`, generic streaming `error`, and transport unavailability receive separate CHALK codes; only an allowlisted reason category may cross into NDJSON, logs, or evaluation evidence.
- Continue the fixed batch without retry only for the clearly topic-scoped `max_output_tokens` and `content_filter` reasons. Stop early on model/reasoning mismatch, missing configuration, HTTP rejection, transport unavailability, or any other/missing upstream reason so an ambiguous or systemic failure cannot consume the remaining budget.
- Count repairs before dispatch, cap each invalid line at two and the entire lesson at four, and retain only the closed generation/repair origin plus bounded count. One topic therefore costs one primary call and at most four repair calls.
- Stop the ten-topic batch on its third machine failure because the 8/10 gate is then unreachable. After a paid-path harness failure, write a redacted v2 summary and do not auto-resume or risk duplicating the call.
- Accept only localhost Host headers at the backend boundary; CORS alone does not prevent DNS-rebinding requests to a server-held credential.
- Keep repair generation on plain text and make local schema/semantic validation authoritative. The second Luna batch proved the repair-only JSON formatting request could be rejected even though official model documentation advertises Structured Outputs support.
- Qualify the corrected seam through a separately approved `repair-smoke` that makes exactly one repair call, retains no generated content, and cannot route to topic smoke or batch. Do not use another ten-topic approval as the probe.
- Default to the accumulated-whiteboard `BOARD_PROMPT_VERSION=v2`, while preserving the exact qualified `v1` prompt as a runtime fallback. Prompt hashes identify the selected version. Never combine v1 rubric evidence with a v2 timing record or relabel retained screenshots after a prompt change.

## Validation

Required deterministic evidence:

- shared schemas compile and generated frontend types are current;
- backend tests cover unsafe expressions, forward/dangling references, duplicate IDs, byte/word/op/step budgets, arbitrary SSE/JSONL chunks, invalid UTF-8/JSON, two-repair-per-line and four-repair-per-lesson caps, repair failure attribution, timeout, upstream failure, post-terminal output, zero accepted steps, batch circuit breaking, crash summaries, hostile Host rejection, and redacted logs;
- frontend tests cover arbitrary NDJSON chunks, blank lines, final newline absence, truncated final lines, request-ID mismatch, abort, terminal envelopes, and cached fallback;
- all ten checked-in golden lessons decode and render without uncaught errors, with the documented overlap check;
- root test, lint, build, npm production audit, schema regeneration, secret scan, and `git diff --check` pass.

Required live evidence:

- one passing bounded Luna access/stream smoke before the larger rubric; the first attempt is retained as failed evidence and does not satisfy this item;
- ten-topic evaluation artifact with prompt hash, model, pass/fail rubric, repairs, drops, first-step/first-visible-stroke timing, screenshots, and human reviewer note;
- at least eight topics pass schema, render, and human layout review; zero renderer crashes.

## Rollback

- Set live generation off in the browser and load the cached projectile lesson through the same decoder/renderer.
- If incremental JSONL is unreliable, generate one bounded complete lesson before playback and record the latency trade-off; do not forward partially trusted output.
- If Luna fails, retain its evidence and compare only failed topics on Terra after explicit approval. Do not consider Sol until both lower-cost tiers show a material quality gap.
- Revert the smallest M3 commit with `git revert`; never weaken validation, expose the server key, or remove the cached path.
